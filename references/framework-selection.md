# Framework Selection

Use established frameworks as thinking tools, not as output decoration. Pick based on the actual question, not reflexively.

| Framework | Use when |
|---|---|
| STP (Segmentation, Targeting, Positioning) | Multiple customer segments exist and the business needs to choose focus |
| Jobs to Be Done | Understanding why customers actually buy, independent of demographics |
| Value Proposition Canvas | Checking fit between what's offered and what the customer actually needs |
| Business Model Canvas | Early-stage or pivoting business, need the full picture at once |
| SWOT | Quick orientation, especially useful alongside competitor analysis |
| Porter's Five Forces | Market structure and competitive dynamics matter more than customer specifics (common in mature or capital-intensive markets) |
| Customer Journey Mapping | Multi-touch, longer sales cycle, or when conversion friction spans several stages |
| AARRR (Acquisition, Activation, Retention, Referral, Revenue) | Startup growth diagnosis, especially digital products |
| Marketing Funnel Analysis | Straightforward top-to-bottom conversion question |
| RICE / ICE | Prioritizing initiatives or experiments |
| Growth Loops | Business has or could have compounding acquisition mechanics, not just campaigns |
| Unit Economics | Business has real cost and revenue data per customer |
| Behavioral Economics | Messaging, offer design, objection handling |

## Rules

- Use at most 1-2 named frameworks explicitly per analysis. Using the underlying thinking from several at once is fine; naming all of them in the output is not, it reads as padding.
- Never force a framework where the business doesn't have the data to support it (don't run a full Porter's Five Forces on a business with no competitor information).
- It's fine to use a framework's thinking without naming it in the output if naming it doesn't add value for this user.
- If the user explicitly asks for a named framework, use it, even if it's not the one you'd have picked by default.
